# Penpot 设计执行约束

> 本文件定义在 Penpot 中按设计系统规范执行设计的约束与流程，不含任何工具函数（Penpot 操作能力由 Penpot MCP 提供）。
> 配套定义见 [system.md](system.md)。

## 1. 设计前：确认配置

1. 读取 [system.md](system.md) 获取系统定义（若尚未读取）。
2. 确认品牌色组：查询 Penpot 令牌库中是否存在 `brand-*` 令牌。
   - 存在：读取并采用，记录本次生效的品牌配置。
   - 不存在：与用户确认品牌色（主色一个值即可，其余按 system.md 配置规则推导）。
3. 确认画板规范：本设计涉及的画板统一 **375px 宽、高至少 814px**（手机一屏），禁止其他宽度。

### 1.1 读取现有项目风格时的只读边界

用户要求从当前 Penpot 项目提炼设计风格时，必须将“读取样本”和“修改设计稿”视为两个独立任务：

1. 只允许读取页面结构、画板尺寸、设计令牌、字体、颜色、圆角、投影、间距和组件命名，并导出代表性画板用于视觉观察。
2. 禁止创建、移动、删除、重命名或修改任何 Penpot 页面、画板、图层、组件、样式和令牌；禁止为方便分析而临时标注画布。
3. 提炼结果写入技能文档，不写回当前 Penpot 项目。任何设计稿优化必须等待用户明确要求后另行执行。
4. 区分“正式令牌”和“实际图层观察值”：令牌是设计系统定义，图层值是作品中的具体表现。二者不一致时分别记录，不擅自统一或修改设计稿。
5. 风格知识必须抽象为可迁移规则，不复制项目名称、业务文案、人员数据或特定任务内容；项目名仅可作为样本来源说明。
6. 多主题项目应提炼共享骨架与主题差异：字体、字号、间距、圆角、组件结构共享，品牌色和状态强调按主题替换；只学习配色方法，不记忆样本项目的具体色相。
7. 用户指定主色后，先构建同色相品牌色组再绘制组件。渐变按钮必须使用该主色的提亮色到主色或同色相加深色，按钮投影也使用该主色透明度变体；除非用户明确要求多色渐变，否则禁止引入其他色相。例如指定绿色时不得自动生成绿蓝渐变。
8. Penpot 渐变几何坐标使用元素内部的归一化坐标。左上到右下线性渐变必须设置为 `startX=0, startY=0, endX=1, endY=1, width=1`；禁止把元素的像素宽高写入 `endX`、`endY` 或 `width`，否则渐变端点会落到元素范围之外。

## 2. 设计中：硬性约束

| 维度 | 约束 |
| --- | --- |
| 画板 | 宽 375px、高至少 814px（手机一屏）；同一页面流程中画板高度按内容增长 |
| 状态栏 | 设计稿必须模拟顶部状态栏（时间、信号、电量等系统元素，高度约 44px），呈现完整视觉效果 |
| 页面边距 | 内容距画板左右 16px |
| 填充色 | 只能用令牌色或令牌值的透明度变体；禁止自定义色值 |
| 文字 | 字体 Noto Sans SC；字号只能取 system.md 阶梯中的档位；行高 1.4（正文）/1.2（标签） |
| 图标 | 统一使用 remix-icon，禁止自定义图形或其他图标库 |
| 圆角 | 只能取档位值（3/5/8/12/13/14/16/20/全圆） |
| 阴影 | 只能用 4 档（卡片/按钮/弹层/聚焦）；颜色跟随元素主色；必须显式设置颜色、透明度、X/Y 偏移、`blur` 和 `spread`，禁止省略模糊参数或默认 `blur: 0` |
| 间距 | 按 8px 网格（8/16/24/32/40）；组件内间距取 12–20px |
| 组件 | 尺寸与特征按 system.md 第 8 节（输入框 58、主按钮 56 等）；描边不是默认属性，必须先判断组件填充与直接背景的对比 |

### 2.1 Penpot 文本与图标防错约束

1. **行高必须使用相对倍数**：Penpot `Text.lineHeight` 只能设置为字符串倍数，如正文 `"1.4"`、标签 `"1.2"`。禁止把计算后的像素值（如字号 14 对应的 `"20"`）写入 `lineHeight`，否则 Penpot 会将其解释为 20 倍行高，造成文字框异常增高、错位和遮挡。
2. **固定文本框必须显式设定边界**：按钮、标签、列表标题、居中文案等文本必须设置 `growType = "fixed"`，并显式设置宽高、水平对齐和垂直居中。仅单行且无需对齐的短文本允许使用 `auto-width`。
3. **禁止字符冒充图标**：禁止使用 `□`、`○`、`✓`、`!`、`‹`、`⌗` 等 Unicode 字符代替界面图标。必须先检索 remix-icon，再以真实 SVG 路径或对应图标资源插入 Penpot；图标名称必须记录为对应 remix-icon 名称。
4. **禁止未经验证的字体回退**：应用 `Noto Sans SC` 后必须检查实际 `fontFamily`、字号和文本边界；若字体不可用，先解决字体应用问题，不得在未知回退字体下批量绘制。
5. **禁止一次性批量生成全部页面**：先完成 1 个包含标题、正文、按钮、卡片、图标的代表性画板，导出 PNG 验证后再继续。每批最多生成 2–3 个画板，避免长调用超时后留下半成品页面。
6. **工具调用失败后必须检查实际写入结果**：出现超时、异常或空文本创建失败时，立即读取当前画板结构，删除或补齐半成品；禁止假设调用已完整成功。

## 3. 视觉验收门禁（交付前必须执行）

同时执行以下两类检查，二者缺一不可：

- **结构检查**：逐画板检查宽高、文本实际高度、元素越界、空文本、缺失状态栏、图标类型和页面内容完整性。常规单行文本实际高度不得异常超过 60px；发现异常时必须定位并修复。
- **投影审计**：逐画板统计带 `shadows` 的图层，并按组件类型逐项核对 `style`、颜色、透明度、`offsetX`、`offsetY`、`blur`、`spread`。标准白色卡片必须为纯黑 `#000000`、3% 透明度的 `shadow-card`（`0/3/12/0`）；彩色主按钮必须为自身颜色的 `shadow-btn`（`0/6/16/0`）；底部弹层或底部导航必须为 `shadow-sheet`（`0/-4/16/0`）；聚焦态必须为 `shadow-focus`（`0/0/6/0`），参数顺序为 X/Y/模糊/扩散。若应有投影的组件数量大于 0、实际带投影数量为 0，或任何常规 UI 投影的 `blur` 为 `0`，直接判定验收失败。
- **描边审计**：逐画板统计带 `strokes` 的容器，检查其直接背景。组件填充与背景已经形成清晰色差时，不得再用描边重复建立边界；白色输入框或白色卡片位于浅灰背景时默认 `strokes = []`。只有同色背景对比不足，或聚焦、错误、禁用、选中等状态确有表达需求时才能使用令牌描边。绘图辅助函数的描边参数必须默认为空，禁止为所有输入框或卡片批量传入 `line`。
- **内部留白审计**：对紧凑卡片、统计卡、快捷操作卡和提示卡，不能只检查元素是否位于容器内。必须取得容器内全部视觉内容（文字使用实际 `textBounds`，图标和图形使用 `bounds`）的联合边界，分别计算 `topGap` 与 `bottomGap`；整数像素下二者差值不得超过 1px。若内容与卡片背景是画板上的同级图层，必须通过几何相交/包含关系收集内容，禁止只读取 `children`。长表单、文章和信息流容器不适用整体居中，但必须遵守顶部内边距档位。
- **嵌套容器宽度审计**：卡片、面板或弹层内的全宽控件必须相对直接容器计算，不得复用画板级坐标。标准卡片内边距为 20px，因此 `controlX = containerX + 20`、`controlWidth = containerWidth - 40`，左右误差必须为 0。绘图函数必须接收容器原点和可用宽度，禁止把页面级 `x=20 / width=335` 硬编码后用于嵌套面板。
- **输入框背景审计**：先识别输入框的直接背景。白色卡片、面板或弹层内的常态输入框必须使用 `bg-input`（`#F5F7FB`）且 `strokes = []`；浅灰页面背景上的输入框允许使用白底无描边形成反向层级。不得用白底加边线修补白色容器中的对比问题。
- **连续 Cell 分隔审计**：垂直连续、边界明确的 `cell` 类结构或信息条，必须在相邻信息行之间使用 `#F5F5F5`、`1px` 分隔线。分隔线属于卡片内部的信息分组，不是卡片描边：禁止加在卡片整体的顶部、底部或左右边缘；首行顶部和末行底部默认不加线。相邻两行之间只允许一条线，禁止上下边线叠加为 2px。分隔线宽度应遵守容器内容内边距，不得无判断地贯穿卡片外边缘。
- **扫码组件审计**：若扫码取景区域已使用四个角标明确边界，取景区域和内部扫描框必须 `strokes = []`，禁止再添加完整矩形描边。扫描线禁止使用单色实心矩形，必须使用横向“透明 → 品牌高亮色 → 透明”的线性渐变；允许叠加同色、非零模糊的柔和发光。渐变端点必须采用元素内部 `0–1` 归一化坐标。
- **图标资源名审计**：按 SVG 根组而不是名称关键词盘点所有可交付图标。每个顶层图标名称必须匹配 `^icon / [a-z0-9-]+-(line|fill)$`，且名称主体必须能在 remix-icon 中检索。禁止顶层图标使用中文名、业务编号或 `svg-g/svg-path`；内部路径层允许保留 SVG 默认名。前端必须能从图层名直接取得 Remix Icon 名称。
- **同组表单图标审计**：先按直接容器、字段层级和控件类型识别表单分组。同一分组中的同类型单行字段必须采用一致图标策略：若任一同级单行字段采用左侧语义图标，其余同类型单行字段也必须有语义匹配的真实图标；图标尺寸、颜色、线型、X 位置、文字起点和图文间距必须一致。多行文本域属于独立控件类型，默认不加左侧图标，文字必须 `verticalAlign = "top"`，并按文本域顶部和左右内边距布局；禁止为机械追求一致而给文本域强加图标。通过 SVG 新建图标后，必须立即把图标追加到目标画板或目标容器，并复核 `parent.id`、画板内边界和图层顺序；仅坐标正确不代表图标已成功放置，禁止在图标仍挂载于其他画板或页面根节点时宣称完成。
- **连续表单状态审计**：识别页面中边界明确、连续排列的完整表单分组。每个分组至少必须有一个合理的预填充示例，同时保留至少一个空态或占位态字段，用于检查已填写文字的主文本色、字重、对齐、图标关系和长内容溢出。预填充值必须符合字段语义，密码使用掩码，且不得使用真实个人敏感数据。若整个连续表单全部只有占位符，直接判定状态覆盖不足。
- **视觉检查**：逐页导出 PNG 并实际查看，检查字号是否可读、信息层级、对齐、上下视觉留白、嵌套左右内边距、输入框背景、颜色、图标、投影、描边必要性、遮挡、截断及页面完成度。结构检查通过不代表视觉合格。
- **交付门禁**：所有画板均完成结构检查、投影审计和 PNG 视觉检查后，才允许向用户报告“已完成”。禁止仅凭画板数量、尺寸正确或元素未越界就交付。

## 4. 风格一致性检查清单（交付前）

- [ ] 所有画板宽 375px、高至少 814px，页面边距 16px
- [ ] 画板模拟了顶部状态栏（时间、信号、电量）
- [ ] 所有色值来自令牌库或档位表（无自定义色）
- [ ] 文本字体 Noto Sans SC，字号来自阶梯，行高符合档位
- [ ] 图标全部来自 remix-icon
- [ ] 卡片=白底+圆角20+纯黑 `#000000` 投影 `0/3/12/0`@3%；输入框=高58+圆角14；主按钮=高56+圆角16+主色投影 `0/6/16/0`@32%（参数顺序为 X/Y/模糊/扩散）
- [ ] hero 品牌渐变左上→右下；分隔线 1px
- [ ] 阴影颜色跟随元素主色，颜色、透明度、X/Y 偏移、模糊和扩散均符合档位，常规 UI 投影不存在 `blur: 0`
- [ ] 品牌色组与本次配置一致（未混入其他主题色）
